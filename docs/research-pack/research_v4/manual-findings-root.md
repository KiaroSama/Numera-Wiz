# FFmpeg manual reading: additional implementation findings

Research date: 2026-10-21. These findings follow actual full-body reading of the ranges recorded in `manual-reading-events-root.json`. The source is the archived `research_v2/ffmpeg-upstream/doc_filters.texi` at FFmpeg commit `946fcce07b6dcd0331c8cc609192aeff5e1924f8`. They are design evidence, not reports of executed media tests. All numerical performance targets in the implementation mandate remain unmeasured until CI or the owner's qualified GPU run records them.

## Application rules derived from the reading

| Finding | Consequence for Numera Wiz | Archived source lines |
|---|---|---|
| `acrusher` changes the signal but does not itself change output sample bit depth. | Model creative bit crushing separately from encoder/sample-format selection; the command inspector must show both when requested. | 718–779 |
| `adelay` accepts milliseconds, `s` for seconds and uppercase `S` for samples. Unspecified channels are unchanged unless `all=1`. | Store delays as typed rational time/sample offsets and explicit channel policy; do not construct bare ambiguous numeric lists. | 895–937 |
| `aecho` supplies finite delay/decay taps. | Offer a native echo effect with those semantics. Do not promise arbitrary recursive donor feedback or generate a huge high-order IIR as the default. | 1209–1275 |
| `afftdn` exposes profile capture and adaptive tracking; `afwtdn` can learn an unsuitable first-frame noise profile. | Noise reduction has explicit profile provenance and preview; never assume the first audio frame is noise. | 1562–1752, 2016–2075 |
| `afir` uses partitioned convolution; partition size trades CPU for latency; `irload=init` prepares every configured IR. | Bound IR duration/channel count and prepared IR count, use frequency-domain native convolution, and estimate latency/memory before accepting an effect. On-demand IR loading is a documented tradeoff, not universally faster. | 1830–1940 |
| `afir` `gtype`, `response`, `channel`, `size` and `rate` are deprecated no-ops; actual normalization is `irnorm` and `irlink`. | Descriptor generation must cross-check actual options and reject obsolete ineffective controls. The upstream example's `irnom=-1` spelling must not be copied into an executable recipe. | 1830–1964 |
| `aformat` negotiates allowed formats. | Do not claim it implements arbitrary channel remixing. Use explicit resampling/remapping/mixing where the operation requires them. | 1965–1992 |
| `alimiter` lookahead adds the chosen attack delay; `latency` compensates and flushes retained samples; automatic `level` is enabled by default. | Pin `latency` and `level` deliberately, verify tails, and keep sample-peak limiting distinct from measured true-peak targets. Upsampling may help but does not itself prove a certified true-peak result. | 2269–2317 |
| Biquad-family `block_size` introduces exactly that many samples of delay; an insufficient reverse-filter block can cause artifacts. | Linear-phase mode needs a bounded cost/latency policy and impulse-response validation. Do not make every EQ linear-phase by default. | 3912–4221, 5045–5168, 5559–5660, 5924–6034, 7275–7476 |
| `anequalizer` silently ignores unavailable channels/frequencies. | Validate channel indices and Nyquist constraints before planning instead of accepting a successful process as proof the requested band was applied. | 2597–2690 |
| `anlmdn`, wavelet denoise and adaptive filters expose very different windows/orders and cost controls. | They are distinct algorithms with useful native schemas. Avoid a universal donor-normalized strength parameter that pretends identical behavior. | 2016–2075, 2691–2810, 3095–3149 |
| `arnndn` always requires a model file. | A capability is unavailable until a pinned, licensed, bounded model asset is installed; no automatic cloud call or undeclared download. | 3150–3171 |
| `aspectralstats` provides flux and other analysis metadata, not an automatic arrangement/remix product. | These metrics can be primitives for a separately specified workflow; they do not justify claiming donor intelligent remix equivalence. | 3310–3377 |
| `asr` uses optional PocketSphinx with matching sample rate and explicit acoustic/language assets. | Gate speech recognition on build components and licensed assets. Do not label general speech/AI behavior supported merely because an ASR filter exists. | 3378–3413 |
| `channelmap` may guess a layout whose order differs from the map; `join` guesses when no map is supplied. | Planner emits explicit channel layouts and maps. Preserve 5.1 versus 5.1(side), channel identities, order and LFE policy. | 4322–4409, 5661–5698 |
| `compand` uses seconds for attack/decay whereas compressor/gate controls commonly use milliseconds. | Internal parameter schemas carry units, and serialization converts once. Display and CLI help must agree. | 4465–4660 |
| `dialoguenhance` produces 3.0 output; `virtualbass` produces 2.1 output. | Adding either effect must disclose and validate the layout change or add an explicit approved downmix; it is not a transparent stereo effect. | 4784–4811, 7512–7531 |
| `dynaudnorm` defaults to 500 ms frames and a centered 31-frame smoothing window. | Treat it as a buffered dynamic treatment, not zero-latency gain or EBU integrated normalization. Include lookahead and retained frames in the plan and preview behavior. | 4827–5033 |
| `firequalizer` zero-phase mode compensates delay by changing timestamps; `fixed` and `fft2` affect performance. | Preserve timeline alignment and validate timestamp effects. Native FIR EQ is a supported option with cost/latency shown. | 5190–5333 |
| `hdcd` produces 20-bit content but a default WAV encoder can truncate it to 16 bits. | Export profiles must explicitly select the requested sample format/codec. Successful filtering is not sufficient fidelity validation. | 5434–5491 |
| `headphone`/`sofalizer` frequency-domain convolution is the fast path; HRTF input mapping and asset formats differ. | Use licensed explicit HRTF assets and bounded frame sizes; no generic stereo IR substituted for the required multichannel mapping. | 5492–5558, 6692–6787 |
| LADSPA/LV2 load executable third-party plugin code and enumerate environment search paths. | Do not enable automatic scanning or remote plugin paths in the default portable build. Such support is separate explicitly installed, qualified capability work. | 5699–5854, 6035–6097 |
| `rubberband` needs an optional native library; only tempo and pitch are runtime commands. | Pitch/tempo preservation can use the native FFmpeg route. Other controls require planned graph initialization/restart and must not advertise live command support. | 6226–6322 |
| Sidechain filters process input1 based on input2 and return one stream; `amerge` combines channels, not a stereo summing bus. | Implement ducking with explicit sidechain routing and a separate intended mix stage. The manual's demonstration is not a ready-made stereo master-bus recipe. | 6323–6475 |
| `silencedetect` emits start metadata after the minimum detection interval, with the value referring to the earlier true start; channels may be separate. | Use the metadata value, not the reporting frame time. Analysis and cut decisions need explicit multi-channel policy and EOF handling. | 6476–6527 |
| `silenceremove` changes timeline length and can rewrite or preserve timestamps. | For linked A/V removal, create an edit decision list from analysis and apply it coherently to video/audio/captions/markers; do not remove audio silence alone and claim synchronization is preserved. | 6528–6691 |
| Many filters support only some options as commands; `stereowiden` excludes delay, adaptive LMS excludes order, and several biquads expose a subset. | Registry records per-parameter initialization/frame-expression/runtime-command support. Keyframability cannot be inferred from a filter-wide command flag. | 2807–2810, 3993–4013, 5640–5660, 6688–6691, 7062–7065 |
| Native `sine` is documented as bit-exact; `anoisesrc` has an explicit seed and finite duration. | Use these for deterministic CI fixtures, with explicit duration/sample rate/layout. Avoid accidental infinite generators and do not blindly copy the suspicious `aevalsrc=-2+random(0)` noise example. | 7901–7997, 8246–8288, 8359–8432 |
| `addroi` attaches metadata and does not change pixels. Its meaning depends on the chosen encoder. | ROI encoding is available only after encoder qualification, not merely because the filter exists; distinguish visual masks from encoder ROI. | 8467–8539 |
| `ass` complex shaping requires HarfBuzz; it supports ASS rather than every subtitle container. | Package the required shaping/font dependencies and test Arabic/Persian joining, mixed direction and font fallback through the actual export path. | 8608–8636 |
| Temporal amplify/denoise filters retain frame windows; `atadenoise` defaults to 9 frames and has an initialization-only window size. | Charge internal filter history to the memory model; preview seek/preroll cannot ignore state. Reducing queue size alone does not bound process RSS. | 8559–8607, 8637–8698 |
| `blackdetect` metadata is emitted regardless of the configured minimum duration, while its reported intervals obey that minimum. | The analysis adapter applies the specified duration to raw metadata and handles incomplete EOF intervals. Black thresholds use input range; a fixed 8-bit threshold is not general. | 8800–8866 |
| CPU `blend` first input is top, second bottom; component expressions override mode options and use per-plane coordinates. | The graph IR has explicit layer order, alpha/color policy and framesync/EOF policy. Native/composed blend presets cannot be assumed identical across GPU implementations or RGB/YUV domains. | 8896–9068 |
| `bm3d` search range is nominally allowed up to INT32_MAX, and smaller steps/more groups increase cost. | UI and registry impose useful bounded operational limits separately from FFmpeg's parser range; do not expose upstream maxima as safe default resource limits. | 9149–9233 |

## Reading limitations

Reading a manual section establishes what the pinned manual says. It does not prove that every example is typo-free, that every optional component is present in the distributed FFmpeg build, that GPU and CPU implementations have identical behavior, or that a chosen setting is fast on the owner's hardware. The mandatory command fixtures, component inventory, source audits and CI/GPU qualification gates must resolve those separate questions.
