## B7-F01 — Browser security headers do not yet define a working WASM/MSE application

**Status: confirmed missing integration contract; runtime qualification pending.**

**Exact mandate anchors:** `research_v6/mandate-architecture.md:141–143` selects shared egui/eframe Glow and Rust-driven DOM/WebGL/MSE. `research_v6/mandate-gui.md:94` selects decoded MSE video uploaded into the shared canvas texture. `research_v6/mandate-delivery.md:55` requires a strict CSP and only packaged assets without selecting the policy, media-source exception or WASM response behavior.

**Why execution is ambiguous:** `script-src 'self'` alone does not authorize WebAssembly compilation under CSP; a streaming WASM response needs its actual MIME type. The browser's selected MSE object URL also needs the media policy to allow that scheme. Borrowing FilmCraft's web bootstrap would additionally import its AudioWorklet/COOP/COEP assumptions even though Numera selected a different media path. An implementer currently has to invent a permissive workaround or discover the contradiction after GUI work.

**Primary evidence:** [MDN WebAssembly streaming compilation](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface/instantiateStreaming_static), [MDN script-src WebAssembly policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src), and [CSP Level 3 media-src](https://www.w3.org/TR/CSP3/#directive-media-src). The archived donor web guide independently requires `application/wasm` and describes a separate single-threaded/AudioWorklet design.

**Selected correction:** adopt B7-C01 in the companion contract: one same-origin packaged bootstrap, explicit MIME/nosniff/cache behavior, a selected CSP allowing only the necessary WASM compilation and blob media, single-threaded browser UI without donor media worklets, and an early packaged-origin boot/playback gate. Keep untrusted artifacts from becoming executable same-origin assets.

**Completion evidence:** the real packaged server boots its embedded WASM, authenticates, displays and audibly plays the selected FFmpeg preview through MSE and shared overlays under the enforced policy in every required browser. Negative fixtures reject wrong WASM MIME, foreign script/API origins, untrusted executable artifact delivery and disabled required policy directives. A static HTML screenshot or development server pass does not close this finding.

## B7-F02 — A scoped top-level media path does not authorize the files a probe can open

**Status: confirmed missing pre-probe boundary; source behavior verified; containment qualification pending.**

**Exact mandate anchors:** `research_v6/mandate-delivery.md:51–57` covers path grants, secondary opens and honest sandbox claims. `research_v6/mandate-domain.md:159` requires all secondary opens in execution plans. It does not select what happens when the *first ffprobe*, before a plan and its dependency closure exist, is handed a playlist, reference movie or sequence pattern.

**Why execution is ambiguous:** `protocol_whitelist=file` is a whitelist of protocol names, not a filesystem-root restriction. A granted playlist may reference a different local file. The top-level extension is not a dependable format boundary. The `concat` demuxer's `safe=1` checks syntax, not authorization of a relative sibling. MOV explicitly has external-track switches; image2 opens a pattern of images. Blocking network protocols alone does not close local secondary reads.

**Pinned primary evidence:** FFmpeg `946fcce07b6dcd0331c8cc609192aeff5e1924f8`: `research_v2/ffmpeg-upstream/doc_protocols.texi:16–20` defines protocol-name whitelisting; `doc_formats.texi:214–215` defines demuxer whitelisting; `doc_demuxers.texi:70–75,209–215,606–611,877–884` describes concat, image2 and MOV external references. `research_v3/ffmpeg-source/libavformat_file.c:492–534` implements seekable `fd:` input and forbids embedding the descriptor number in its URL. See the [pinned file protocol source](https://github.com/FFmpeg/FFmpeg/blob/946fcce07b6dcd0331c8cc609192aeff5e1924f8/libavformat/file.c), [protocol manual](https://ffmpeg.org/ffmpeg-protocols.html), and [demuxer manual](https://ffmpeg.org/ffmpeg-formats.html). Some live manual fetches timed out; the pinned archived texts above were actually read.

**Selected correction:** B7-C02 admits ordinary probing through one already-authorized seekable regular-file descriptor, with the `fd` protocol as its only protocol and an explicit audited demuxer class. Reference-bearing sources take a typed dependency resolver before probing; unresolved formats fail with a specific import reason. Actual execution receives only the frozen, authorized source/reference closure. This narrows deliberate FFmpeg secondary opens and does not claim to sandbox a compromised native decoder.

**Completion evidence:** CI exercises the actual bundled ffprobe on all native targets, including a seek near the end of an MP4 through the descriptor route; misleading extensions; concat/HLS/image sequences; MOV external references; authorized and unauthorized sibling/symlink targets; and a network canary. The ordinary probe cannot access the canaries or fall back to unrestricted paths. Required supported imports receive a real resolver/route, not reclassification as “optional”.

## B7-F03 — Agent parity lacks a bounded representation for seeing and retrieving media

**Status: confirmed missing wire/resource contract; coordinated with the product observation contract.**

**Exact mandate anchors:** `research_v6/mandate-domain.md:277–300`, “MCP and direct HTTP”, promises previews and opaque artifact resources; `research_v6/mandate-domain.md:341`, D6-J04, requires an agent to read the result artifact; `research_v6/mandate-delivery.md:18` caps normal pages at 256 KiB. Neither whole-file resource reads nor a private owner URL can safely be inferred from those statements.

**Why execution is ambiguous:** a movie can be gigabytes, while MCP binary/resource/image/audio content is serialized into protocol messages. Returning an artifact ID alone does not let an agent inspect a rendered frame. Returning arbitrary-size base64 defeats the memory and transcript constraints. Returning a private IPC bearer or query-token URL defeats the separate effective-principal model. This gap is independent of whether the semantic `previews.observe` request is well designed.

**Primary evidence:** official [MCP tool content types](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) and [resource reads](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) define protocol representations, not Numera's media budgets or object access policy. Modern resources may be filtered by request authorization and do not need subscriptions to exist.

**Selected correction:** B7-C03 uses standard image/audio tool content for bounded `previews.observe`, a JSON manifest resource for large artifacts, authenticated bounded-buffer HTTP downloads or an explicitly granted native destination for full files, and an explicit small `artifacts.read_chunk` fallback for stdio. Product semantics remain owned by `previews.observe`; transport byte limits are selected once. All paths reuse object-read authorization; possession of an opaque ID grants nothing.

**Completion evidence:** CI verifies a real frame/audio observation with matching revision/time/display identity, an over-budget result preserving its original artifact and returning `INLINE_BUDGET_EXCEEDED`, a multi-gigabyte logical artifact with bounded memory, exact resumable reads, expired/revoked/other-principal denial, and zero owner-token/path leakage in resource results. Run both selected MCP versions on stdio and HTTP using their SDK-produced envelopes.
