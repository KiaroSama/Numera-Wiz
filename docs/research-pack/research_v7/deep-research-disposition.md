## Claim-by-claim decisions

| Report item | Primary-source assessment | Selected consequence and acceptance linkage |
|---|---|---|
| 1. RTSP whitelist bypass and HLS fix status at FFmpeg 9.0.2 | The report conflates separate defects. The pinned RTSP source contains the non-RTSP redirect-scheme rejection, and the pinned HLS parser uses the fixed child-playlist open path. The distinct RTSP 3xx path still loops without a redirect counter in this exact pin. See the complete-source security triage/archive; do not label the fixed scheme/HLS defects active in this pin. | Retain deny-by-default ordinary file probing and explicit network-source admission. Do not advertise unchanged direct RTSP; select and qualify an exact corrected component/route before enabling it, closing any required baseline row before release. A protocol name or a fixed advisory is not destination authorization. Do not adopt `-reconnect 0` as redirect control. B7-J02 and the existing security gates own the malicious-manifest/redirect/destination/deadline cases. |
| 2. Mandatory filter API migration and state reset on any parameter change | The inspected CLI still accepts textual filtergraphs; the report's `avfilter_graph_parse_ptr2` migration claim is not supported by the pinned interface and is irrelevant to the selected subprocess integration. Actual input reinitialization can discard filter state and buffered frames. Commands, expressions, topology changes and input format epochs are distinct. `tpad` is video padding; `asetpts` changes timestamps. | Reject the proposed API switch and arbitrary state-reset policy. Retain `reject_unexpected_change`, qualified reconfiguration observation, finite dependency windows and continuous/materialized state islands. MF7-J01 through MF7-J04 and the earlier compiler cases provide the relevant independent oracles. |
| 3. Donor headless wgpu fallback must recur in Numera | A donor issue is not proof of a Numera defect. Numera does not inherit the donor's media compositor or its wgpu adapter-selection path; its selected ordinary UI seed is Glow and its media computation is FFmpeg. An active GUI adapter also says nothing about hardware decode/filter/encode availability. | Keep explicit stage/device/transfer-path selection and diagnostics, CPU-only qualification, device-absent/failure cases, and exact-artifact owner GPU qualification. Do not add another donor compositor or assert a non-null Vulkan adapter as the oracle for FFmpeg acceleration. Existing R22/D6-G06 and media planning cases already require the relevant behavior. |
| 4. Native/browser color and transparent content cannot agree | The general concern about interpretation, transfer/range, alpha and signaling is valid. The report contradicts itself about egui blending and offers an invalid universal 127/128 half-white oracle. Linear-light half-white encoded as sRGB is approximately 188; encoded-space blending gives approximately 128. Opaque H.264 cannot carry independent alpha, but it can carry an engine-composited image over the declared background, with disclosed transport loss. | Keep `PreviewDisplayContract`: common declared display target, FFmpeg view transform/composition, native texture import rules, browser YUV/VUI/MSE presentation and actual-browser comparisons. Distinguish source fidelity from preview transport tolerance. Do not introduce WebCodecs or a new media renderer solely because the report proposed it. MF7-J05 applies. |
| 5. A granted top-level filename does not confine its internal references | This is a valid boundary. The pinned `fd:` implementation can use an already-open seekable regular-file descriptor; its default nested-protocol setting means the explicit profile still matters. A broad `file,fd` whitelist would not restrict arbitrary sibling paths. The report's particular DASH/CVE/version assertion is not established by the inspected evidence and must not become a product claim. | Keep the reserved fd-only ordinary probe, admitted demuxer classes, disabled external-track options, and explicit bounded resolvers for reference-bearing inputs. Preserve dependency identities and resource/network policy before probing. Reject a 512-byte magic-prefix check as complete admission, a generic allow-network flag as complete policy, or reconnect options as redirect enforcement. B7-J02 applies. |
| 6. Unbounded MCP media can exhaust memory | Official MCP defines typed image/audio content, resources and resource links; Numera must select its own limits and client behavior. The report's proposed universal 512 KB base64 ceiling is not a protocol rule. A resource URI alone does not ensure an agent will retrieve usable pixels, and unrestricted `file://` exposure is incompatible with the selected access model. Protocol-version/session claims must be kept separate for the supported versions. | Keep actual bounded inline observations, manifest fallback preserving the same artifact identity, explicit chunk requests and authenticated streaming. The selected limits distinguish encoded file bytes, metadata and complete serialized response. Do not stream an entire movie through `resources/read` or assume automatic link fetching. P7-J05/B7-J03 and both protocol/transport profiles apply. |
| 7. WASM requires compatible CSP and MIME | The WebAssembly CSP model and MDN streaming-instantiation documentation support an explicit compilation policy and `application/wasm`. The exact packaged assets and browser matrix still need qualification. The report assumes wgpu and external static hosting, which are not Numera's selected deployment. Old-browser fallbacks do not justify widening policy for the supported matrix. | Keep the concrete local-owner response headers, hashed embedded asset namespace, single-thread WASM seed, MSE blob use and packaged boot tests. Do not add nginx deployment, a separate web host, broad `unsafe-eval`, cross-origin isolation or worker/shared-memory scope without an actual selected requirement. B7-J01 applies. |
| 8. Donor MCP wrappers silently ignore some fields/errors | The report does not establish the cited issue-fix ancestry at the pinned commit, and its chronology is internally inconsistent. Even a confirmed donor parser defect would not automatically recur in Numera's independently generated typed registry. A static occurrence of a field name cannot prove semantic implementation. | Keep semantic parameter acceptance/rejection fixtures, shared domain errors and official MCP tool-error formatting. A successful job-status query may report a failed job without itself being a failed query. No generic arbitrary `ffmpeg.command` tool or donor expression engine is introduced. B7-J03 and the generated parity/parameter suites apply. |
| 9. Ephemeral dialog preferences prove sequence-FPS corruption | The described ripple-checkbox state is not proof that a sequence setting silently changes stored clip duration. The source/read-model and selected timing contract are the relevant evidence. A fixed donor tick denominator is not a universal substitute for checked rational clocks or an explicit snapping policy. | Keep elapsed authored time when FPS changes, authored geometry by default, explicit supported geometry scaling, and duration/pitch preservation on sample-rate changes. Return one atomic compatibility/invalidation report with undo. Rebuild derived media under a new captured revision without rewriting authored time to guessed frames. P7-J04 applies. |
| 10. Unknown fields in an extension map establish forward compatibility | Merely retaining JSON is insufficient when unknown nodes affect render semantics or unknown major/envelope versions cannot be interpreted safely. Blog readiness percentages and generic absolute-path claims do not define this project's acceptance. Numera already selects its own versioned project schema and managed/linked/relink behavior. | Keep supported bounded opaque envelopes, read-only unsupported major/envelope versions, affected-closure render rejection for enabled unknown semantic nodes, and explicit migration/rollback. Do not adopt absolute-only media references, silent no-op effects or donor-native project compatibility as new requirements. P7-J03 and the retained migration/relink journeys apply. |
