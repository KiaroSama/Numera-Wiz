# Numera Wiz revision 6: product-completion review

**Review date:** 2026-10-22. **Reviewed baseline:** revision 5.0. **Evidence status:** source and specification review only; no application, FFmpeg graph, browser, build, CI job or GPU test was executed.

## What this review changes

Revision 5 already names the required editing domains and most important safety boundaries. Its remaining product problem is the distance between those statements and a complete user journey. A list of panels, command IDs and one acceptance sentence per domain can still leave an implementation agent to invent incompatible asset lifetimes, edit boundary policies or animation clocks.

The ten findings below close those concrete seams. They do not add a cloud service, another renderer, a plugin host, donor pixel-identity requirements or a new product family. `product-workflows.md` supplies proposed integrated wording. The root mandate should incorporate the wording into its existing asset, edit, GUI, domain and completion sections; it must not become a second competing specification.

## Source observations supporting the corrections

- **Source monitor intake:** `crates/ui-egui/src/panels/source_drag.rs` snapshots the selected source and marked range when a drag begins and separately supports video, audio and both. This supports an explicit source-patch/selection snapshot rather than reading changing UI state during commit. [Pinned source](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/ui-egui/src/panels/source_drag.rs#L1-L38)
- **Edit distinctions:** the pinned edit crate has separate overwrite, insert, lift, extract, ripple delete, group ripple trim, roll, slip, slide and rate-stretch implementations. `insert` affects targets and eligible sync-locked tracks; `roll` and `slip` are not move aliases. This review reads those operations as behavioral evidence and selects safer explicit Numera boundary policies rather than importing every donor internal implementation. [Pinned edit functions](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/edit/src/lib.rs#L260-L365) · [Grouped trims and source-handle operations](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/edit/src/lib.rs#L725-L1103)
- **Animation-clock ambiguity is real:** `project/src/keyframe.rs` describes clip-relative times, but `TrackItem::effect_time_at` explicitly returns media time and supports a separate “hold filters” choice. `engine/src/keyframe_move.rs` maps a common timeline delta to key times through signed speed and validates their visible source range. The mandate must encode the chosen clock rather than inherit an ambiguous comment. [Parameter model](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/project/src/keyframe.rs#L1-L7) · [Effect clock](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/project/src/lib.rs#L633-L664) · [Grouped keyframe move](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/engine/src/keyframe_move.rs#L43-L108)
- **Automation modes:** the pinned mixer model stores track lanes in sequence time and explicitly defines Off, Read, Latch, Touch and Write. The Numera recording controller must preserve these useful mode distinctions while rendering through FFmpeg. [Pinned mixer model](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/project/src/mixer.rs#L1-L18) · [Modes](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/project/src/mixer.rs#L75-L119)
- **Shared workspace identity:** donor floating groups retain the same panel identities, and the shared docking adapter validates serialized layouts before application. This is appropriate presentation logic to preserve without copying donor media processors. [Dock model](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/ui-egui/src/dock.rs#L452-L477) · [Shared adapter](https://github.com/storytold/filmcraft/blob/d643a886650bfbf16f24762274054575aa1e8f20/crates/ui-egui/src/dock_shared.rs#L54-L84)

## Review boundary

The source observations above were read from the already archived exact donor revision. No current upstream feature status, working Numera binary, passing graph, performance result or complete donor-pixel identity is inferred. The upload retention and conflict policies are selected Numera designs closing gaps between already-required workflows; they are not claims about the donor's existing safety behavior.

The proposed addition deliberately reuses the v5 worker, durable receipts, source/destination grants, UI crate, command registry, FFmpeg planner and CI policy. Its tests belong in those existing suites. It does not mandate a second framework or another round of broad repository research before implementation can continue.
